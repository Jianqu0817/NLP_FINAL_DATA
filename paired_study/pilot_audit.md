# 原始 pilot 复核：微调改进了外壳、数据，还是规则？

主测试一共 580 题。严格按接口交付一个 `{"schema":…,"data":…}` 对象时，Base、Adapter、LoRA 的联合成功数分别是 **121、209、279**（20.9%、36.0%、48.1%）。然而，Base 常把内容写成前后相连的两个对象。仅补这一层外壳，Base 就从 **121 增至 204**（35.2%）。它与 Adapter 的净差由 88 题缩至 5 题，与 LoRA 的净差由 158 题缩至 75 题。净差缩小不代表两模型在每道题上犯的是同一种错。

## 拆开三种成绩：整套规则、数据、联合交付

原始严格结果沿用[原报告](../results/pilot_summary.md)。下表是**事后诊断**：对三种方法应用相同的补壳规则，每格为通过题数，分母为该行所有请求；未能提取一对对象的题仍记失败。`规则`指预测 Schema 接受全部正例且拒绝全部反例；`数据`指原评分器归一化后与参考实例完全相同；`联合`还要求格式、Schema 规范合规性及自洽性等全部通过。

| 测试轨（题数） | Base：规则 / 数据 / 联合 | Adapter：规则 / 数据 / 联合 | LoRA：规则 / 数据 / 联合 |
|---|---:|---:|---:|
| 明示要求、未见 Schema（500） | 162 / 286 / 140 | 133 / 378 / 133 | 208 / 381 / 203 |
| 口语会议、已知 Schema（80） | 80 / 64 / 64 | 80 / 76 / 76 | 80 / 76 / 76 |
| 独立挑战集（100） | 36 / 45 / 19 | 31 / 52 / 17 | 30 / 55 / 13 |

会议轨原本三者的联合成功数是 0、76、76。Base 的 80 个输出均可补壳，补壳后三者的 Schema 都通过全部见证，剩下的差距在实例数据。要求驱动轨中，Adapter 比补壳 Base 多交付 92 个正确数据对象，却少交付 29 个通过整套规则测试的 Schema。LoRA 在此轨同时改善了两项；在挑战集上，LoRA 的正确数据仍较多，但完整规则与联合通过数都低于补壳 Base。

## 同一道题、两边均可评分时，谁真正改对了规则？

在 500 道要求驱动题中按 ID 配对，仅比较整套规则是否通过，不要求输出的数据正确。“外壳可解析”接受原样或机械补壳后的合规外壳；“规则可执行”进一步要求两份 Schema 均可按评分器支持的方言与关键字执行。各方法可评分的题不同，因此下表每行只描述该行的共同子集。

| 比较 | 配对条件 | 题数 | 仅 Base 通过 | 仅微调模型通过 |
|---|---|---:|---:|---:|
| Base / Adapter | 双方外壳可解析 | 376 | 63 | 28 |
| Base / Adapter | 双方规则可执行 | 264 | 61 | 19 |
| Base / LoRA | 双方外壳可解析 | 380 | 16 | 36 |
| Base / LoRA | 双方规则可执行 | 266 | 11 | 18 |

在两边规则均可执行的 266 题中，LoRA 相对 Base 净多过 7 题；另外 133 题两者都过，104 题两者都不过。在 Adapter 与 LoRA 同时给出合规 Schema、且数据都完全正确的 314 题上，LoRA 独过 64 题，Adapter 独过 24 题。差异不全来自输出外壳或数据抽取。

## 三条原始回答解释了分数的含义

- **LoRA 相对 Base 的规则胜例** — `test_sales_contract_order_001` 明说不得增加其他字段。Base 与 LoRA 的输出外壳、抽取数据均正确。向买方对象加入 `"unexpected_field":"extra"` 时，Base 的 Schema 仍放行，LoRA 拒绝。此题的差别就是规则，不是格式。
- **Base 原有能力被外壳遮住的例子** — `test_warehouse_pick_pack_011` 要求三个包裹，每个都有物流单号、SKU 和件数。Base 写成两个连续的对象，补壳后与 LoRA 一样通过全部见证，且数据正确。Adapter 也抽对了这三个包裹，却漏了数组元素的 `required`，因此把第一个包裹换为 `{}` 也能通过其 Schema。
- **参考规则超出题意的例子** — `test_customer_quote_001` 规定了报价编号格式，却只说客户对象含客户编号与公司名。参考 Schema 另要求 `customer_id` 匹配 `^C[0-9]{5}$`；示例值 `C00001` 不能推出这项通用约束。这个模板的 25 题沿用该参考规则。Adapter 在该例猜中参考格式，LoRA 遵循字符串约定却被扣分。应将成绩称作“通过参考见证”，而非“所有自然语言要求均处理正确”。

本次比较使用一个基座、每种微调方法一个训练种子、模板生成的数据。500 道要求驱动题来自 20 个模板族，每族 25 题。有限见证能揭示具体过宽或过窄的规则，但不能证明 Schema 完全等价。

## 复算

在项目根目录执行：

```text
python -B paired_study/pilot_audit.py
```

[脚本](pilot_audit.py)读取 `runs/{base_zero,adapter_lr0.0001_seed42,lora_lr0.0001_seed42}/{test,challenge}.jsonl` 中的原始输出与冻结严格成绩，并按 ID 对齐 `data/` 下同名输入及预先生成的正反例。它仅对原格式失败、且全文恰好包含两个连续合法 JSON 对象的输出补上键名及外壳，次序为 Schema、数据；不改对象内容、不剥代码围栏，也不修重复键或第三个对象。然后用[原评分器](../scripts/evaluation.py)重评这些输出，其他输出沿用原成绩。原始 Base 在三轨分别补壳 30、80、91 次，两个微调模型均为 0 次。脚本向标准输出打印包含完整配对四格计数的 JSON，不调用模型。

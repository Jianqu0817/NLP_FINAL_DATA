# 配对规则测试协议（冻结版）

## 测试回答什么

在具体材料和正确数据不变时，只改一条中文要求，模型生成的 Schema 能否随之改变。该测试用于分析既有冻结 checkpoint 的规则敏感性；它不单独证明对未见规则组合或真实用户请求的泛化。

## 固定设计

- 共 48 个最小对、96 行：`count_bounds`、`required_optional`、`nullable`、`conditional_dependency` 各 12 对。
- 每对的场景、字段名、材料事实、输出格式及通用规则完全相同，仅替换 `build_pairs.py` 中一个 `clauses` 条目。变化不含显式 JSON Schema。
- 每对两臂具有完全相同的 `reference_data`，且同时通过两份参考 Schema。具体材料值不转写成 `const`。
- 数量组比较两个交叠但互不包含的数组长度区间，共同材料位于交点。必填组只改变一个字符串字段能否省略；可空组只改变一个必填字符串字段能否为 null。条件组交换同一枚举判别字段的两个值中哪一个触发另一个字段必填，另一分支明确可选。
- 每族内 A/B 规则方向各占 6 对，按种子 `20261113` 打乱；输出行也确定性打乱。A/B 本身不代表更严格的规则。条件材料所在分支也交替变化。
- 所有字段名、类型、枚举、必填/可选、空值和额外字段要求均在输入中明确。参考 Schema 使用根目录 `DATA_CONTRACT.md` 与 `scripts/evaluation.py` 的 Draft 2020-12 支持范围。

## 判别探针与共同控制

每行 `probes` 含 `id`、`instance`、`accept`。同一对两臂的探针 ID、实例和顺序完全一致；标签只由各臂参考 Schema 的验证器产生。

- 数量组：区间两侧各有一个方向相反的判别实例；共同正例包括参考材料及合法替换内容；共同负例包括同时越界、错误元素类型、缺字段和额外字段。
- 必填组：缺目标字段是判别例；字符串替换和空字符串是共同正例；null、数字、对象、缺始终必填字段和额外字段是共同负例。
- 可空组：目标字段 null 是判别例；缺目标字段在两臂均为负例，防止混淆“可空”和“可省略”；其余类型与字段控制同上。
- 条件组：分别去掉两个判别分支的目标字段，形成双向翻转；两分支均含字段及合法替换文本是共同正例；两分支中的 null、未定义枚举、缺判别字段、错误类型和额外字段是共同负例。

## 生成、验收与冻结

此数据是模型辅助编写场景模板、固定种子确定性生成的合成集，无独立人工标注。`build_pairs.py` 未调用模型或服务。

运行 `python paired_study/build_pairs.py` 可创建文件；文件已存在时只核对确定性内容并验证，不覆盖任何差异。内置检查覆盖 48 对/96 行及分族计数、行键、唯一 ID、参考数据有效性、Schema 支持范围、探针标签、跨臂实例一致、共同正负例、判别翻转，以及数量/条件组双向翻转。

本次冻结对象为 `pairs.jsonl`，应在任何 checkpoint 推理之前固定；看过输出后不调整测试要求、参考 Schema 或探针。若发现数据错误，另行记录版本和原因，原冻结结果不混入修订版本。该有限探针集用于测量已列实例上的行为，不是 Schema 逻辑等价性证明。

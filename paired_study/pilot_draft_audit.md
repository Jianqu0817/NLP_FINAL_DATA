# 放宽 Schema 关键字白名单后，原始 pilot 的规则优势还有多少？

允许按 Draft 2020-12 执行项目白名单以外的 Schema 后，**要求驱动轨上 Base 的全见证通过数从 162 增到 176，Adapter 仍是 133，LoRA 从 208 增到 209**。LoRA 相对 Base 仍有净优势，但从 46 题缩至 33 题。两边都能实际执行 Schema 的 378 道题上，净差只有 7 题。挑战集上方向相反：Base 通过 36 题，Adapter 31 题，LoRA 30 题。

## 同一份原始回答，同一组冻结见证

下表均先对所有方法作[相同的机械补壳](pilot_audit.md)，再比较“原项目规则评分 → 放宽白名单的 Draft 评分”。每格是接受全部正例且拒绝全部反例的**题数**，分母含格式错误和 Schema 不可执行的请求。此处只评价 Schema，不混入生成数据的正确率。

| 方法 | 要求驱动（500） | 已知 Schema 会议（80） | 挑战集（100） |
|---|---:|---:|---:|
| Base | 162 → **176** | 80 → 80 | 36 → 36 |
| Adapter | 133 → 133 | 80 → 80 | 31 → 31 |
| LoRA | 208 → **209** | 80 → 80 | 30 → 30 |
| Base + 一个异题格式示例 | 118 → 118 | 50 → **51** | 13 → **15** |

三个原方法中，要求驱动轨可执行 Schema 数分别从 292、465、451 增至 401、465、460。Base 有 109 份过去不能评分的 Schema 现在可执行，其中只有 14 份通过整套见证。

## 成对比较：LoRA 为什么多过 33 题？

按要求驱动轨同一个请求 ID 配对，在放宽后的口径下计算：

| 方法顺序 | 纳入题目 | N | 仅左侧通过 | 仅右侧通过 | 双方均过 |
|---|---|---:|---:|---:|---:|
| Base / LoRA | 全部 | 500 | 39 | 72 | 137 |
| Base / LoRA | 双方 Schema 都能执行 | 378 | 25 | 32 | 137 |
| Base / Adapter | 全部 | 500 | 91 | 48 | 85 |
| Base / Adapter | 双方 Schema 都能执行 | 372 | 68 | 21 | 85 |
| Adapter / LoRA | 双方 Schema 都能执行 | 435 | 24 | 89 | 97 |

因此 LoRA 相对 Base 的 33 题净差中，7 题来自双方都能执行的子集，另 26 题来自至少一方不能执行的子集。后者体现交付可评分 Schema 的能力差异，不能算作两份可用 Schema 之间的规则理解差。挑战集全部 100 题里则是 Base 独过 16、LoRA 独过 10（双方均过 20）。

## 被恢复的通过，不等于之前错判了模型

Base 在要求驱动轨新通过的 14 题分为两组：7 份招聘 Schema 含未知关键字 `nullable`，7 份供应商 Schema 含旧式 `dependencies`。评分器按 Draft 行为执行其余部分，不把前者翻译成可空类型，也不把后者映射成 `dependentRequired`。LoRA 新通过的 1 题含多了前导空格的 `" minLength"`，同样不修正。挑战集的格式示例对照另恢复 2 题，均含 `nullable`。

**具体反例：** `test_recruiting_candidate_001` 要求邮箱和电话必须且只能填一个。Base 的 Schema 写死了邮箱必填，却在放宽白名单后通过了该题全部冻结见证。对同一参考记录删掉邮箱，改填有效电话 `13700000001`：参考 Schema 接受，Base Schema 拒绝。因而这项指标衡量的是**有限见证**，不是精确规则等价；新增的通过不能一概解读成模型掌握了对应规则。

## 复算

在项目根目录运行 `python -B paired_study/pilot_draft_audit.py`，生成[完整计数、逐项恢复 ID 与配对表](pilot_draft_audit.json)。[脚本](pilot_draft_audit.py)沿用[配对诊断](semantic_probe.py)的 Draft 2020-12 与 FormatChecker 口径：缺失方言标记可执行，显式错误方言、Schema 引用、元 Schema 无效仍失败。已经可执行的 Schema 复用原见证成绩，只对新可执行的 Schema 运行见证。不会修正或翻译关键字，也不调用模型。该分析不更改原项目对单对象接口及支持关键字的交付要求。
